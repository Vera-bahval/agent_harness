# CLI: CP1-06

CLI — отдельный процесс Python 3.12, который обращается только к публичному HTTP API gateway. Docker и ключ модели клиенту не нужны. Десктоп-оболочка остаётся задачей ЧП2.

## Запуск из корня проекта

```bash
make setup-client   # один раз: локальный токен, без вывода секрета
make up
make demo-client    # replay Б1.1, без платных запросов
```

`setup-client` сохраняет отображение principal → token в CLIENT_TOKENS локального .env и первый токен в `.local/client.token` (права 600). Существующие ключ модели и токены сохраняются. Эти файлы исключены из Git. Без CLIENT_TOKENS gateway отвечает на healthcheck, но отклоняет все запросы v0.

Эквивалентный запуск напрямую:

```bash
python3 -m client.cli run 'На каком порту слушает сервис? Запиши число в answer.txt.' \
  --pair replay-b1 --output results/local/client-result.tar
```

CLI выводит session_id, run_id, trace_id, затем события с event_id и финальный результат. После успеха скачивает tar, проверяет размер и SHA-256, закрывает сессию. Архив автоматически не распаковывается и его содержимое не исполняется.

Для настоящей модели: `--pair first-real-pair --timeout 180`. Настройки OpenAI остаются только на сервере; такой запуск использует API-баланс. Проверка CP1-06 проводилась на replay.

Адрес и токен: глобальные аргументы `--url` и `--token-file` ставятся перед подкомандой. Альтернатива файлу — переменная CLIENT_TOKEN. Передавать сам токен аргументом CLI не нужно.

## Отмена и повторное подключение

Ctrl+C в `run` отправляет run.cancel, ждёт подтверждённого финала и закрывает сессию. Из другого терминала можно выполнить:

```bash
python3 -m client.cli cancel SESSION_ID RUN_ID
python3 -m client.cli watch SESSION_ID RUN_ID --after 3
```

Заменить идентификаторы значениями из вывода. `watch` только читает существующий запуск, не создаёт новый и не закрывает сессию. После разрыва потока CLI переподключается с последнего полученного event_id; повторы событий отбрасываются. Если история уже истекла, клиент запрашивает run.get; завершённый результат возвращается, для активного запуска сообщается об утрате истории. CLI `run` закрывает сессию в finally, включая потерю соединения после принятого запуска; `watch` предназначен для наблюдения за ещё существующей сессией.

Для нескольких сообщений в одной сессии доступен Python-клиент [Client](cli.py): connect → session.create → run.start → wait → следующий run.start → session.collect → download → session.close в finally. История и /work сохраняются между успешными run. CLI run намеренно представляет одну законченную задачу; интерактивный чат можно добавить поверх того же API.

## Границы

- Порт опубликован только на 127.0.0.1. Для другой машины — SSH-туннель или TLS-прокси; токен передаётся заголовком Authorization.
- SSE-соединение живёт ограниченное время; его окончание не отменяет работу. Перезапуск gateway меняет epoch и закрывает старые сессии: это не обычный reconnect.
- Gateway — один процесс, состояние в памяти. Токены задаются JSON-объектом в CLIENT_TOKENS; разные principal не видят сессии и артефакты друг друга. Несколько gateway одновременно не поддерживаются.
- После ошибки/таймаута/cancel сессия не принимает новую задачу: нужно закрыть её и создать новую. После нормального финала можно продолжать.
- Readiness проверяет процессы и зависимости, но не баланс провайдера. HTTP-сервер предназначен для локальной учебной разработки, не для публикации в открытый интернет.

## Проверки

`make test-ui` — 8 проверок клиента и настоящего HTTP/SSE gateway с mock-харнесом: авторизация, владение ресурсами, повтор запросов, конфликт, события, reconnect, дедупликация событий, cancel/close, epoch и курсоры.

`make test-client` — 3 сквозных сценария через работающий Compose: Б1.1 с проверкой схем событий и архива; два сообщения с сохранением файлов и истории; отмена/конфликт/reconnect. Внешняя модель не вызывается.

Документы: [контракт v0](../contracts/README.md), [gateway и сессии](../docs/client-gateway.md).

`make test-gateway-lifecycle` — отдельная dev-проверка SIGKILL/restart gateway при активной команде. Отказывается запускаться при уже существующих сандбоксах; проверяет новый epoch и очистку старой сессии.
