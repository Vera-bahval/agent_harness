# ADR-0004: HTTP JSON и события между харнесом и manager

- Статус: proposed
- Дата: 2026-11-04

## Контекст

Харнес должен исполнять команды только через явный версионированный контракт.

## Предложение

Предлагаются HTTP-операции provision/exec/collect/release/cancel и поток событий. Exec получает operation_id и deadline, выдаёт один логический result; переподключение может повторно доставить то же событие, но не повторно исполнить команду.

## Альтернативы

gRPC/protobuf: строгая типизация, но генерация кода и инфраструктура сложнее для старта. Очередь задач: полезна для устойчивости, но вводит брокер и сложную семантику доставки на раннем этапе.

## Последствия и проверка

В v0 явно описать дедупликацию, срок хранения результата и потерю состояния после restart. Ошибки команды не ретраить автоматически; timeout требует остановки; transport_error требует запроса состояния, а не слепого повторного exec. Проверки схем дополняются поведенческими тестами одного result, idempotency и cancel.
