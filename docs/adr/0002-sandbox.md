# ADR-0002: Docker-сандбокс через host socket

- Статус: accepted для CP1-04; hardening продолжается к ЧП2
- Дата: 2026-11-04

## Контекст

Нужны отдельная среда для пользовательских команд, квоты, отмена дерева процессов и запуск из чистого клона через Compose. Пользовательские команды не должны исполняться в manager или харнесе.

## Решение

Один Docker-контейнер на сессию. Manager использует Engine API v1.45 через host socket, работает от UID 0 и один имеет socket mount. Команды — от UID 10001 в контейнере, с read-only rootfs, cap-drop ALL, no-new-privileges и network none. Docker-параметры выбирает только manager.

/work — tmpfs с реальной квотой, /tmp и shared memory тоже ограничены. Это временное решение для фикстур ЧП1; удалённое монтирование остаётся ADR-0005/ЧП2. Сервисный токен manager генерируется в shared volume; harness получает только read-only доступ к этому volume.

Отмена/таймаут останавливает весь контейнер и теряет /work. Такой выбор даёт понятную проверяемую гарантию остановки даже detached-процессов. После остановки доступно чтение результата и release, дальнейший exec/collect запрещён. Collect обычной завершённой команды разрешён, только если в контейнере нет фоновых пользовательских процессов.

## Альтернативы

| Вариант | Преимущества | Цена / почему пока не выбран |
|---|---|---|
| Host Docker socket | простой воспроизводимый запуск и доступ к cgroup-лимитам | компрометация manager фактически даёт root хоста |
| Rootless Docker | daemon без root хоста | настройка daemon/cgroups/mounts требует отдельной проверки целевой машины |
| gVisor | дополнительная граница изоляции syscalls | установка runtime на хосте и проверка совместимости |
| Kill только process group | можно сохранить сессию и /work | detached children могут выйти из process group; для надёжной отмены нужен отдельный механизм |
| Named volume для /work | сохраняет файлы после остановки | Docker volume сам не обеспечивает простую дисковую квоту; риск остаточных данных |

## Последствия

Manager — доверенная часть с root-equivalent правами; эта архитектура не защищает хост от взлома manager. Остальные сервисы и сандбоксы socket не получают. Root используется внутри сандбокса только фиксированным seed-скриптом для установки ro-фикстуры до пользовательских операций; команды агента никогда не получают root.

Read-only /work реализован root-владением и запретом записи через права Linux, а не read-only флагом mount: это нужно для начального заполнения tmpfs. Проверяется и WriteFile, и прямой shell-записью/chmod. При полноценном удалённом mount понадобится отдельная политика ro/rw.

Очистка: release, idle TTL, SIGTERM и удаление старых контейнеров по метке до ready при restart. SIGKILL не запускает cleanup, поэтому сандбоксы могут жить до перезапуска manager. Атомарное восстановление после сбоев и full hardening не заявлены.
