# ADR-0006: Одна активная задача на сессию

- Статус: accepted
- Дата: 2026-11-04

## Контекст

Нужно связать workdir, события, состояние харнеса и ресурсы сандбокса.

## Решение

Одна сессия принадлежит одному клиентскому principal, имеет один сандбокс и не более одного активного run. Повторное подключение возобновляет чтение событий; не создаёт новый run. Параллельные сессии имеют разные workdir и идентификаторы.

## Альтернативы

Новый контейнер на каждый tool call: проще локальная очистка, теряется рабочее состояние. Несколько параллельных run в сессии: быстрее, но появляются гонки правок; для v0 отклонять вторую задачу как conflict.

## Последствия и проверка

Состояния и переходы определить в контракте. В v0 restart может завершать активные сессии ошибкой, после чего manager собирает оставшиеся ресурсы. TTL сессии, лимит событий и дедупликации нужно зафиксировать числами до реализации. Проверки: чужая сессия недоступна, конфликт двух run, изоляция двух сессий, очистка и reconnect.

## Спецификация v0

Предложение конкретизировано в [контрактах](../../contracts/README.md) и [семантике](../../contracts/semantics.md): маршруты, состояния, численные лимиты, повторные запросы и restart. Проверено в CP1-06: [реализация и ограничения](../client-gateway.md), `make test-ui` и `make test-client`.
