# Архитектурные решения

Приняты и проверены ADR-0001, 0002, 0003, 0004, 0006, 0007 и 0008. ADR-0005 (mount) остаётся proposed до эксперимента на ЧП2.

| ADR | Решение | Когда проверить |
|---|---|---|
| [0001](0001-harness.md) | свой небольшой харнес на Python | CP1-01 / CP1-05 |
| [0002](0002-sandbox.md) | отдельный Docker-контейнер на сессию | CP1-01 / CP1-04 |
| [0003](0003-client-transport.md) | HTTP + SSE для клиента | CP1-02 / CP1-06 |
| [0004](0004-sandbox-transport.md) | HTTP + поток событий для manager | CP1-02 / CP1-04 |
| [0005](0005-workdir-mount.md) | кандидат: SSHFS через обратный туннель | исследование к ЧП2 |
| [0006](0006-sessions.md) | один активный запуск на сессию | CP1-02 / CP1-06 |

Позже добавить ADR сетевой политики и выбора пары по фактическим БАФ (обязательный минимум A-10). Шаблон: [0000-template.md](0000-template.md).

[0007](0007-network-policy.md) — сетевая политика; выбор пары для ЧП1 описывается отдельно от итогового сравнения нескольких пар на ЧП3.

[0008](0008-cp1-model.md) — выбор отдельной допущенной пары для ЧП1.
