# План до первого чекпоинта

Статус на 2026-11-05: CP1-09 выполнен, 15/15 на cp1-sol-low; CP1-10 подготовлен локально, [готовность](readiness.md). История этапов: контракты v0, сервер и сандбокс реализованы; агентный цикл CP1-05 проходит replay и реальный Б1.1 на gpt-5.4-mini. CP1-06: CLI/gateway реализованы. CP1-07: раннер готов. CP1-08: пять простых Б1–Б5 проходят на replay и реальной модели, результаты сохранены.

**Цель:** из чистого клона поднять сервер, подключить клиента и провести реальную задачу по пути клиент → gateway → харнес → LLM-прокси / sandbox-manager → сандбокс. Затем воспроизводимо прогнать Б1–Б5 и показать результаты.

Источник требований: [ТЗ A](https://github.com/deeppavlov/agentic-course-itmo/blob/b42540f5215b4ad30820bdd0330c466ba19e19e1/projects/A-agent-runtime.md). Ниже — наш порядок работ и критерии готовности, а не дополнительные требования преподавателей.

## CP1-04. Реализовать сандбокс

- [x] `sandbox/Dockerfile`: минимальные инструменты для Б1–Б5, непривилегированный пользователь.
- [x] Manager: provision → exec → collect → release; отдельная временная `/work` на сессию.
- [x] RunCommand возвращает раздельные stdout/stderr/exit_code; ReadFile и WriteFile работают в `/work`.
- [x] Таймаут команды, cancel с остановкой дерева процессов, один финальный result; повтор release безопасен.
- [x] Минимальная защита с первого запуска: без сети, без socket/ключей внутри сандбокса, CPU/RAM/PIDs, cap-drop, read-only root, no-new-privileges; отдельное место для временных файлов.
- [x] Ограничение диска выбрать и проверить отдельно: переменная SANDBOX_DISK сама квоту не создаёт. Полная проверка A-5 — к ЧП2.
- [x] Manager помечает создаваемые ресурсы и очищает их после сессии/сбоя. Динамические контейнеры вне compose не удаляются автоматически через down.

Готово: через протокол создать файл и прочитать его, увидеть ненулевой exit code, прервать зависшую команду и проверить отсутствие контейнеров/процессов после release. Отдельно проверить, что canary-секрет сервера не доступен агенту.

Реализация и ограничения: [docs/sandbox.md](sandbox.md). Проверки: `make test-sandbox`, `make test-lifecycle`, `make demo-sandbox`. Cancel/timeout завершает всю сессию с потерей временной /work. Это ещё не агентный цикл и не результат БАФ на LLM.

## CP1-05. Реализовать харнес и LLM-прокси

- [x] Прокси: replay для CI и адаптер настоящего провайдера, таймауты и нормализованные ошибки/usage.
- [x] Харнес: system + user + история tool calls/results → LLM → валидация → sandbox → наблюдение → следующий шаг.
- [x] Реестр RunCommand, ReadFile, WriteFile; отсутствие локального fallback на subprocess в харнесе.
- [x] Условия остановки: финальный ответ, max_steps, deadline, cancel, невосстановимая ошибка. Ограничить размер вывода инструмента.
- [x] Выбор харнеса/модели через `configs/pairs/`; модель не меняется внутри прогона.
- [x] JSONL-трейс: идентификаторы, операции, длительности, исходы, токены. Секреты редактируются/не логируются.
- [x] Заполнить `docs/harness.md` реальными ссылками на код.

Готово: replay вызывает команду через сандбокс, получает результат и завершает цикл; реальная модель затем решает Б1.1 тем же путём. Ошибка инструмента возвращается модели как наблюдение, а не выдаётся за успешный ответ.

Проверки: `make test-harness` — 8 сценариев. Реальный Б1.1 прошёл 2026-11-05, курсовой чекер вернул pass=true; [детали и ограничения](harness.md), [отчёт](report.md).
