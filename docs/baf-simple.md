Курсовые формулировки взяты из [catalog.yaml](../baf/catalog.yaml). Б1.1 — исходный курсовой пример; для Б2.1…Б5.1 созданы собственные фикстуры и чекеры по этим формулировкам.

| Задача | Действие агента | Содержательная проверка |
|---|---|---|
| [Б1.1](../baf/B1-read/B1.1-service-port/task.yaml) | Прочитать порт | answer.txt = 8137 |
| [Б2.1](../baf/B2-search/B2.1-find-function/task.yaml) | Найти определение parse_date | Путь app/helpers/dates.py, а не файл импорта/вызова |

| [Б4.1](../baf/B4-edit/B4.1-install-version/task.yaml) | Изменить версию только в Install | README побайтно совпадает с эталоном одной замены; notes.txt не изменён |

В Б2 есть определение, импорт, вызов в тесте и упоминание в README: чекер принимает только путь определения. В Б4 версия 1.2 встречается также вне Install, поэтому глобальная замена не проходит. В Б5 выбраны данные с разными средним и медианой. Чекер Б5 проверяет численный результат и неизменность входов; наличие RunCommand видно в трейс-событиях. Сам правильный ответ не доказывает способ вычисления.

## Команды

```bash
make up
make baf-simple-smoke  # пять задач, одна пара replay-simple, без внешней LLM
make baf-simple-real   # пять задач, first-real-pair, по одному платному прогону
```

Обе команды используют раннер CP1-07 и публичный API. На каждую задачу создаётся свежая сессия, исходная fixture сверяется по содержимому, итоговый архив проходит доверенный checker на хосте. Сырые результаты, события и архивы сохраняются в results/baf. [Описание раннера](../baf/runner/README.md).

`replay-simple` выбирает сценарий по однозначному фрагменту задачи, исполняет нужные инструменты и проверяет наблюдения. Для Б2 используется реальный grep, для Б5 — python stats.py data.csv. Это детерминированная инфраструктурная проверка с заранее заданным ответом, не измерение качества модели.

## Регистрация и изоляция

[fixtures.json](../baf/fixtures.json) связывает task_id с source_id для раннера. Серверный allowlist — [services/common/fixtures.py](../services/common/fixtures.py); его используют gateway, harness и manager. Менеджер получает только fixture-подкаталоги через явные COPY в Dockerfile и allowlist .dockerignore. check.py, task.yaml и скрытая JSON Schema в контейнеры не копируются. Для нового source_id нужно обновить обе регистрации и сборку manager.

## Проверки чекеров

[tests/unit/test_simple_baf.py](../tests/unit/test_simple_baf.py) проверяет положительные и отрицательные случаи:

- Б2: верный путь, файл вызывающего кода, тест, абсолютный путь и отсутствие ответа.
- Б3: верный JSON, неверные типы, пропущенный/лишний/дублирующийся ключ, переставленный массив.
- Б4: одна верная замена, отсутствие правки, глобальная замена версии, смена переводов строк, лишняя пустая строка и изменение другого файла.
- Б5: 7 и 7.0, неправильное число, NaN, текст вместо числа, изменённые входные данные и отсутствие ответа.
