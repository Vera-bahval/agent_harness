Все 15 задач оформлены как task.yaml + fixture + доверенный check.py. Средние задачи и задачи с подвохом конкретизируют формулировки из курсового catalog.yaml.

## Проверки

Новые чекеры используют общий доверенный baf/checks.py. Его SHA-256 отдельно сохраняется в JSONL. Для каждой новой задачи проверены отсутствие результата, правильный результат и неправильный; Б4.2 дополнительно отвергает исполняемые изменения вне допустимого AST до вызова функции. В Б5.2/Б5.3 checker проверяет неизменность исходного проекта.

Чекер переименования намеренно строгий: Python AST должен совпасть с исходным после замены имени; форматирование может отличаться, семантические изменения не допускаются. Только после сравнения AST компилируется pricing.py с единственным разрешённым builtin sum и вызывается на четырёх скрытых примерах. Импорты app/tests на хосте не выполняются.

## Запуск

```bash
make baf-cp1-replay           # 15 задач без модели/ключа
make baf-cp1                 # cp1-sol-low, 15 задач, один повтор, платный API
make baf-cp1 PAIR=first-real-pair # контрольная mini, допуск по AA не подтверждён
make baf                    # все оформленные задачи, три повтора; Б6–Б8 ещё впереди
```

Replay-cp1 выбирает наиболее конкретный совпавший маршрут из текста задачи; одинаковая специфичность отклоняется. Это фикстура ответов модели, которая действительно исполняет команды и проверяет наблюдения. Сценарии с nonzero exit возвращают модельному циклу failed-observation и продолжают до записи ответа.

Серверный реестр — services/common/fixtures.py, registry раннера — baf/fixtures.json. Оба включают все B1_1…B5_3. Dockerfile manager и .dockerignore явно включают только fixture; task.yaml, checks.py и check.py остаются на доверенной стороне.

Результаты и сравнение с контролем — [отчёт](report.md). Разовый успех 15/15 не является оценкой устойчивости; полноценное сравнение нескольких пар и расширение Б6–Б8/составных остаются дальнейшей работой.
