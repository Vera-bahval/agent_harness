# Agent Harness — среда исполнения агента

Учебный проект задания A курса ИТМО × DeepPavlov. Цель — построить сервер исполнения агента, подключить десктоп-клиент с удалённым монтированием рабочей папки и сравнить пары «харнес + LLM» на БАФ.

**Сейчас:** подготовлена структура на основе курсового шаблона, план ЧП1 и черновики решений. Исходников сервисов, Dockerfile, работающего клиента и раннера пока нет. ЧП1 ещё не выполнен; `docker-compose.yml` — заготовка.

Начать с [плана ЧП1](docs/checkpoint-1.md). Затем прочитать [архитектуру](docs/architecture.md), [ADR](docs/adr/README.md) и [разбор источников](docs/sources.md).

## Структура

```text
client/                    будущий десктоп-клиент и его CLI
services/
  gateway/                 входной API: токен, сессии, сообщения, события
  harness/                 цикл LLM → инструмент → наблюдение
  sandbox-manager/         создание, исполнение, отмена, удаление сандбоксов
  llm-proxy/               доступ к провайдеру модели; ключ только здесь
sandbox/                   образ среды, внутри которой исполняются команды
contracts/                 два версионированных протокола
configs/pairs/             конфигурации пар харнес + LLM
baf/
  catalog.yaml             курсовой каталог задач (описания, не готовый набор)
  B1-read/                 готовый курсовой пример Б1.1
  runner/                  место для собственного раннера
tests/                    contracts, unit, ui, infra, fixtures/llm
docs/                     план, архитектура, ADR, харнес, БАФ, отчёт
results/                  сырые результаты БАФ, трейсы, замеры
scripts/                  будущие команды проверки и демонстрации
```

## Команды

Сейчас доступны `make help` и `make plan`. Остальные цели завершаются ошибкой с пояснением, пока соответствующий этап не реализован: заглушка не должна выглядеть как успешный тест.

Целевой порядок после реализации CP1-03…CP1-10:

```bash
cp .env.example .env        # заполнить локально, не коммитить
make up                    # docker compose up --build -d
make test-ci               # детерминированные проверки без внешней сети
make baf-cp1 PAIR=first-real-pair  # Б1–Б5, 15 задач, 1 повтор
make down                  # удалить compose-ресурсы и сандбоксы сессий
```

Это будущий интерфейс команд, а не инструкция запуска уже работающей системы. Проверка качества требует настроенной разрешённой модели; mock/replay проверяет инфраструктуру и не доказывает качество LLM.

Версии зависимостей и образов фиксируем при реализации. Модель, её версия, параметры и Intelligence Index на дату выбора попадут в `docs/report.md`.
